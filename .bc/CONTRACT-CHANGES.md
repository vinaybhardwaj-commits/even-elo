## A. Pre-commit edits (already in af10d9a, after the first draft of CONTRACT.md)
1. `Stat` gained an optional `extra` object (M-OPD-02 `{counts, pct_a, pct_ab, pct_ce, basis}`; M-OPD-05 `{pct_notes_with_one_or_more, notes_with_one_or_more, pct_ci95, ci_method}`; M-OPD-06 `{banded_coverage, expected_rate, raw_rate}`).
2. Units: `Stat.value` follows `unit` (percent = 0-100). Inside V3/V4 rows the raw rate fields (`value` for lv_rate, `rate`, `ci95`, `expected_rate`, `centre`, funnel limits, `share_of_gap`, `site_rate_without`) are FRACTIONS 0-1.
3. Three module-local count ids (not catalogue metrics): `M-SIG-01`, `M-WL-01`, `M-WL-02`; `unit:"count"`, never min-n gated.
4. V5 dossier: no `n_notes`. Signal objects also carry `doctor_uid, doctor_name, site`; `response_required` is a boolean (false when stored as none/empty). Signals are open threads, not windowed.
5. `total` appears on V5, V8 and drilldown results.
6. Fixtures are generated by the real SQL over a seeded scratch DB and shape-checked by a test.
7. Access matrix: `tests/access_matrix.json` NOT changed on the agent branch; `.bc/access_matrix.cdmss.json` is the finished matrix, copied in at merge with B's `access.ts`.

## B. A2 changes (23 Oct)
1. **V2 `view.sites` changed type**: was `string[]` (e.g. `["ALL","SITEA"]`), now `[{code,label,n}]` (ALL first, then every site with notes in the window, sorted by code; `n` = canonical notes in the window; `label` = code for now). The old string list is now `view.matrix_sites` (the rows present in `matrix`, which honours the `site` param). **Breaking for anything that read `sites` as strings.**
2. **V2 `view.band_mix`** (new, family `opd` only): `[{site, counts:{A..E}, bands:{A..E: Stat}}]`, one entry per `matrix_sites` row. Each `bands[x]` is a Stat: metric_id `M-OPD-02`, `band` = the letter, value = percent of PDQI-assessed notes in that raw band, Wilson CI, n = assessed notes, same min-n and coverage greying as every Stat. For `family:"ams"`, `band_mix` is `[]`.
3. **M-OPD-02 `extra.band_stats`** (new): `{A..E: Stat}` as above, so `cdmss_metric` and V1 tiles carry the per-band shares too.
4. **V4 `view.sites`** (new): same `[{code,label,n}]` shape as V2, all sites in the window (not just the requested one).
5. **`case.url_verified`** (new, always `false`) on every `case` object: evidence rows in V5 and `cdmss_finding_detail.view.case`. Label the link as unverified in the UI.
6. Transport/access rulings recorded in CONTRACT.md section 0: dedicated route `/api/cdmss/[view]`, no `tool-schema.ts` change, reviewers deferred.
